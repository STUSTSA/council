# 行政會議流程與即時回報卡片：決策規格

定案日：2026-11-16（決策對話，DievE 授權決策端判斷）。對照基準：分支 `claude/phase-03`（PR #63）的 `docs/DESIGN.md` 與 `docs/交接說明.md` 第九十五節。

標記沿用 CLAUDE.md：**定**＝可以實作；**想**＝只討論、不實作。
這份文件只記決策，不含實作。03（#63）不因這份文件修改，以下都是 03 之後的工作。

## 一、要解決的問題

依 114-1 第八次、114-2 第四次、115-1 第九次與第十次行政會議資料：

- 同一張卡片在會議資料出現多次。第十次學權部「會議報告事項」9 項、「本週完成」14 項，8 項重複，一項在同一區出現兩次。原因是每週概述按區塊各自列卡片，一張卡符合幾個條件就出現幾次。
- 其他部門手打，標題、進度、提醒混在一起，顆粒度不一。
- 秘書處要的是：每個部門只列當週要報告事項的標題。
- 會議紀錄寫在原項目下方，會議中常出現原本沒列的新事項。
- 活動結束後的核銷、成果冊、檢討書反覆逾期。

## 二、報告標記與會議資料

1. **定** 一張卡在一份會議資料裡只出現一行，只列標題，不分區塊。
2. **定** 「報告」標記指向下一次行政會議。沿用現有的「會議要報告」開關與紅色小字，不是標籤，不進標籤設定。
3. **定** 秘書處面板即時讀取各部門標了報告的卡片標題，依部門順序排列；沒有報告事項的部門照現況列在一行小字。部門不需要另外繳交。
4. **定** 秘書處按「定版」後，當下清單存成該次會議資料，之後部門改卡片不影響這一份。
5. **定** 秘書處輸出會議紀錄＝該次會議結案，報告標記隨之失效。做法是標記記錄它指向哪一次會議，會議結案後視為未標；秘書處不寫入部門卡片。
6. **定** 有標報告但當週沒有編輯的卡片照樣列出。

資料位置：定版的會議資料與會議紀錄存在秘書處的資料區；可見範圍照已定決策，任何已登入帳號唯讀。

## 三、編輯次數（取代「第幾段」）

1. **定** 卡片狀態列的「第幾段」改成編輯次數；「完成這一段」拿掉。
2. **定** 一次編輯＝一次有內容變動的儲存。03 的原位編輯是點外面一次存入全部修改，所以一次編輯過程就是一次；沒改只收合不算。
3. **定** 每次編輯留一筆紀錄：誰、何時、改了哪些欄位，可看改前改後。來源是版本歷史，不另存一份。
4. **定** 次數顯示在卡片展開後的標題旁，點了看紀錄。會議資料不顯示次數。
5. **定** 部門的每週概述只列有標報告的卡片，一張一行，後面寫當週是第幾次到第幾次編輯，每次可點開。自動產生。
6. 連帶要重定的現有規則（實作時處理，不另問）：
   - 燈號規則裡「這週完成過一段＝白」拿掉，改成只看每週回報期限前後有沒有編輯。
   - 03 暫定決策 8、34（完成這一段的預填與說明替換）隨功能移除而作廢。
   - 已存的段落資料不刪，舊卡片的段落紀錄仍可在編輯紀錄裡看到。

## 四、會議中的操作（秘書處）

1. **定** 定版後照議程逐行進行。點標題展開該卡最新內容與當週編輯紀錄，唯讀。
2. **定** 每行下方是秘書處的紀錄區，欄位：人（負責人）、事（決議，動詞開頭）、時（交付期限）、地（場域或成果路徑）、物（原因、風險、限制），另加一個自由文字欄。全部可留空。分開列出，不組成句子。
3. **定** 會議中出現的新事項，秘書處在該部門底下建一張待批准的卡，同樣帶上述欄位。
4. **定** 部門面板出現「待併入」清單：本次會議對自己卡片的紀錄，以及待批准的新卡。可逐項按，也可一次全部併入。
5. **定** 併入的結果：「事」加「時」「地」成為卡片的一個時間行（帶核取框）；「物」與自由文字成為文字行；「人」加進卡片的專員。這次併入算一次編輯，紀錄註明來自哪一次會議。
6. **定** 紀錄原文留在會議紀錄不變；併入後的卡片由部門照常編輯。
7. **定** 下一次會議資料最前面自動列「上次決議追蹤」：每項完成、逾期、改期或未併入。

**與現況不同，實作前先回報影響範圍**：現在的做法是會長室開放後，秘書處直接修改部門卡片，寫回時自動記成會議紀錄（DESIGN「會議報告事項」「秘書處會議編輯與會長室授權」）。本節改成秘書處只寫自己的紀錄、部門併入。會長室的開放開關、寫回機制、會議紀錄 PDF 的內容來源都會受影響。

## 五、清點區

1. **定** 只收有期限、核取框還沒勾的時間行。03 的時間行本來就是時間加核取，不需要改資料結構。
2. **定** 放在通知層最上面，分三段：已過期、本週到期、之後。
3. **定** 已過期的每一項只有兩個動作：完成、改期。沒有移除。
4. **定** 通知鈕的紅色數字把已過期的件數算進去。
5. **定** 負責人維持掛在整張卡（專員），不做逐行負責人。原因：逐行負責人要在 blocks 加欄位並改規則（03 暫定決策 2），第一版先不動。

## 六、即時回報卡片

對照 DievE 2026-11-16 提供的四張設計圖。

1. **定** 沿用 03 的資料結構與逐行內容（文字、核取、時間三種行），不重做資料。
2. **定** 卡片底部工具列依設計圖：文字、人、時間、地點、核取、超連結，左側是母議題選單。工具列是新增該種行或打開該欄位的入口，取代每一行前面的「種類」下拉。
3. **定** 右上「報告」按鈕與左右切換鈕依設計圖。
4. **定** 時間輸入：預設現在時間，分鐘取到 5 分鐘。桌面可用滾輪調整，但要先點一下選中才生效，滑鼠只是靠近只顯示可調狀態，避免捲動頁面時誤改。選中時可直接輸入數字。滾輪一格：日期 1 天、小時 1 小時、分鐘 5 分鐘。
5. **定** 手機沿用 03 的自製時間選取器。不用瀏覽器原生外觀。
6. **定** 人的分頁拿掉說明文字「從本看板的身分挑選，可複選」（03 暫定決策 19 保留的那一句），依「介面不放教學說明文字」。
7. **定** 03 暫定決策 a（時間選取器自製）、b（點外面儲存、沒有取消、提供復原）照用。c（長按 0.38 秒拖曳排序）沒有討論，維持現況。

## 七、專案

1. **定** 「專案」是跟部門同級的獨立單位，由活動部管理：活動部管理員建立專案、用 QR 邀請總召成為該專案的編輯者。不新增角色種類。
2. **定** 首頁兩種檢視：部門、專案。專案的呈現形式跟部門分開。
3. **定** 專案卡同樣可標報告、被記錄、併入、進清點區。會議資料的「專案追蹤」讀這個單位標了報告的卡。
4. **想** 每個專案帶一排固定的收尾項目（核銷、成果冊、檢討書、公假名單等），各自有期限並進清點區。DievE 尚未同意，項目內容也未定。

這一節會多一個單位，動到 02B 的權限設計，開工前先回報要改的規則。

## 八、會議順序的編輯權限

| 項目 | 可以改的人 |
|---|---|
| 議程大項順序 | 秘書處、會長室 |
| 部門之間的先後 | 秘書處、會長室 |
| 部門內各項的先後 | 定版前該部門；定版後秘書處、會長室 |
| 專案之間的先後 | 秘書處、會長室 |
| 定版後增刪項目 | 秘書處 |

## 九、標籤設定

1. **定** 維持現況：人事時地物標籤由管理員在設定頁建立；專員只能選本看板的身分；「地」標籤是時間行地點的快速選項。
2. **定** 「報告」不是標籤。
3. **想** 標籤改名或刪除時舊卡片怎麼處理、全會層與部門層各管哪些類別。尚未討論。

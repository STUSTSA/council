# 工作報告調查（只讀；HEAD 3bb4b9d，report.js 與 board.css 報告段跟 origin/main 相同）

## 結論
1. 【驗證】Chromium 印出的 PDF 跟視窗寬度無關（桌面 1300、Pixel 7、412 寬的 PDF 文字完全相同）。不一致的是「預覽的預測」：桌面預覽預測第 5 頁起從第 17、35、53 段開始，PDF 實際是 18、37、56；手機預覽預測 18、36、54。頁數剛好都是 9，rp2.js 只比頁數所以沒抓到。
2. 原因：
   - A【驗證】vw 字級：列印時 1vw＝內文寬 1%，預覽量螢幕寬。`.rpt-ch-n`、`.toc-n`、`.cv-mid h1`、`.cv-sub` 用 clamp(…vw…)：章號桌面預覽 80px、PDF 約 62px、手機預覽 48px → 每章第一頁預測差一段。
   - B【驗證】甘特圖的「今天」膠囊與靠右的月份標籤超出紙寬（706px > 688px），Chromium 把整份縮成約 0.964 倍；預設期間結束日＝今天，所以大部分報告都會被縮。加 overflow:hidden 後只剩 A 的誤差。
   - C【推論】真的手機瀏覽器：iPhone（WebKit）不支援 @page 頁碼、紙張可能是 Letter；Android 紙張由系統對話框決定；afterprint 太早觸發可能讓空白章被重新編號。要實機確認。
   - 根本原因：讓瀏覽器自己斷頁，預覽用另一套量測去猜（`rptPaginate` 預測、`rptPrint` 前 `rptUnpage` 清掉）。
3. 分頁線：紅色虛線 `.rpt-pb`（紙寬不到 210mm 才畫，含「第 N 頁從這裡開始」膠囊）、`.rpt-gap`、`.rpt-pg`；`@media print` 隱藏、印前也清掉，PDF 裡確認沒有【驗證】。只有用螢幕截圖方式產生 PDF 才會被拍進去【推論】。真的會印出來的線：議題間 `.rpt-issue` 虛線、章首下 1.5px 實線。
4. 舊分支 `ccr-4452d757-4vq5ip`：跟 main 沒有共同祖先（歷史改寫過），不能合併；它的斷頁（七十五 `7682907` 逐行預測、七十九 `04ac720` 整段不切）已經在 main；直接用會弄壞會議紀錄（`openReport` 第三個參數、`rptDoc`）。沒有可沿用的新東西；`rptLines` 只在以後要讓長段落跨頁時可參考。

## 現況缺口（摘要）
- 封面：WORK REPORT、網址、製表日期不能改；日期出現兩次。目錄沒有頁碼。章只能加在最後、移除不能復原。文字沒有粗體／條列／表格／連結。圖片不能裁切、並排。卡片三欄在手機畫面變兩欄、列印仍三欄。摘要只有週報數量。甘特圖不能改且超出紙寬。議題逐案是一大塊，不能單獨移除、排序。
- 格式：日期三種寫法、「｜」「・」混用、字級不統一、列印帶強調色、頁碼從封面算且 iOS 不支援。
- 匯出：只有瀏覽器列印；手機檔名常無效；iPhone 安裝版可能叫不出列印；預覽關掉修改就沒了。

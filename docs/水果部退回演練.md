## A. 退回 GitHub（演練重點）

順序不能換：先讓新資料庫不能再寫，才匯出。

1. **你手動**：會長室管理 → 人員。如果有人（除了你這個總管理員）有「水果部」角色，點那個人 → 水果部那列按「撤銷」。**把名字和原本角色抄下來**（B-3 要還）。沒有別人就跳過。之後到第 5 步為止，你自己不要改水果部的任何東西。
2. **你手動**：水果部看板 → 設定 → 備份 → **匯出備份**，存下 JSON 檔（檔案有內容，不要貼到群組，存在只有幹部看得到的雲端資料夾）。**抄下匯出時間**，例如 `2026-11-21 14:30`。
3. **你手動**：用兩個畫面對照這一份備份：看板上的卡片張數與標題，跟剛剛的記憶一致。
4. **請工頭**：開 PR，只把 `dept/config.js` 水果部那一行的 `source: "firestore"` 拿掉。你看過、驗收通過、合併後，等 1～2 分鐘，重新整理 `?d=fruit`。看板現在讀 GitHub 的 `data-fruit.json`（設定裡多出「匯入備份」）。
5. **你手動**（檢查匯出後有沒有人偷偷寫入）：用總管理員在同一個瀏覽器打開 `?d=fruit`（已登入 Google 的那個）→ 按 F12 → 「Console」→ 貼下面三行（只把時間換成第 2 步抄的；Chrome 若要你先輸入 `allow pasting` 就照打）→ Enter。只會印兩個數字，不顯示內容：
   ```js
   const F = await storeFsGet(), since = Date.parse("2026-11-21T14:30:00+08:00");
   [(await F.versionsSince(CFG.firebase, "fruit", since)).length,
    (await F.auditSince(CFG.firebase, since)).filter(a => fsAuditDept(a) === "fruit").length]
   ```
   - 印出 `[0, 0]`：可以繼續。
   - 不是 `[0, 0]`：**停**。有人在匯出後寫了東西（通常是第 1 步漏撤）。撤乾淨後從第 2 步重新匯出，把新數字截圖給工頭。
6. **你手動**：在看板（現在是 GitHub 模式）用舊方式登入（水果部是測試部門：全會密碼 → 你的身分）→ 設定 → 備份 → **匯入備份** → 選第 2 步的檔案 → 確定。看到「已匯入並儲存」就是寫回 `data-fruit.json` 了（GitHub 上多一筆 commit，是看板自己存的，屬正常）。卡在登入或權杖：截圖給工頭，不要自己去 GitHub 發權杖。
7. **你手動**：對照第 3 步，卡片都回來、內容一樣＝**退回成功**。

**角色先不要還**（原因見 `遷移步驟.md` A.4 第 8 步）。到這裡演練的主要目的已達成；要不要接著做 B 看你決定。

## B. 再切換一次（建議做；水果部之後還要當測試場）

新資料庫還留著水果部上一次的資料。匯入程式只「新增、相同跳過、不同列衝突」，**不會刪**，所以要先清掉。目前匯入頁沒有「清空這個部門」「回復這一批」，必須在主控台手動刪。

1. **請工頭**：開 PR 把水果部那行加回 `source: "frozen"`（凍結）；合併後 `?d=fruit` 顯示「正在搬到新資料庫，暫停編輯」。另外請工頭先給你當下 `main` 的 commit（40 碼）與 `data-fruit.json` 的 SHA-256（64 碼）。
2. **你手動（Firebase 主控台，正式專案 `stustsa-council`，Firestore Database → Data）**：
   - 先看 `cards`、`events`、`issues`、`weeks`、`labels` 這五個集合，**抽幾份文件確認 `deptId` 都是 `fruit`**。只要看到別的部門代號（例如 `rights`），**整件事停下，截圖給工頭**，不要刪。
   - 都是 `fruit` 才刪：這五個集合各按「刪除集合」；`cards` 會問要不要一併刪子集合（`versions`），要。再刪文件 `deptSettings/fruit`。
   - **不要刪**：`legacyIdentities`、`roles`、`auditLogs`、`departments`、`migrations`。
   - 刪完每個集合都應該是空的。
3. **你手動**：網頁匯入頁（會長室管理 → 匯入）→ 水果部（標「凍結中」）→ 填第 B-1 的 commit 與 SHA-256 → 核對通過 → 匯入，看報告：寫入的數量對、衝突 0。
4. **請工頭**：開 PR 把 `source` 改回 `firestore`；合併後重新整理。
5. **你手動**：把 A-1 抄下的人的角色還回去（人員 → 改角色，或重新發 QR）；確認看板可以編輯、存檔。
